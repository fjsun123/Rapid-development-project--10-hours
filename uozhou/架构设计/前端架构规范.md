# 前端架构规范

> 适用范围：[apps/dashboard/](../apps/dashboard/)（后台管理 Expo Web）和 `apps/mobile/`（商家+客户 App，Expo Native + Web）
>
> 核心约定：**MVVM 模式（React hooks 实现）**，让 View 与业务逻辑解耦，便于测试和复用。

---

## 1. 技术栈（强制）

| 层 | 技术 | 用途 |
|---|---|---|
| 项目 | Expo SDK 51+ + Expo Router (file-based routing) | 文件即路由，Web/Native 同源 |
| 语言 | TypeScript 严格模式 | 全代码静态类型 |
| 服务端态 | React Query (TanStack Query v5) | 网络请求缓存、自动 refetch、乐观更新 |
| 本地态 | Zustand + `persist` middleware (AsyncStorage) | 购物车、登录态等跨页本地状态 |
| 表单 | react-hook-form + zod（schema 来自 [packages/types](../packages/types/) 生成产物） | 校验和提交 |
| 网络 | axios + Orval 生成 client（[packages/api-client](../packages/api-client/)） | 接 OpenAPI 契约链 |
| 鉴权 | JWT 存 `expo-secure-store`，axios interceptor 注入 `Authorization` | 安全存储 |
| 样式 | `StyleSheet.create` + 设计令牌（[packages/shared/tokens](../packages/shared/)） | 不用 NativeWind/Tamagui，避免运行时开销 |
| 图标 | `@expo/vector-icons`（已内置） | 跨端图标 |
| 国际化（如需）| `i18n-js` | 后台默认中文 |
| 测试 | Vitest（hooks/utils 单元）+ Playwright（E2E） | |

**禁用**：Redux、MobX、RxJS、styled-components、Emotion、CSS Modules（理由：MVVM 用 hooks 即可，不需要外部状态库；样式用 RN 原生 StyleSheet）

## 2. MVVM 分层

### 2.1 三层划分

```
┌─────────────────────────────────────────────────────────────┐
│  View                                                       │
│  - 纯函数组件，只接收 props，只渲染 UI                       │
│  - 不直接调 API、不直接读 store                              │
│  - 不写业务逻辑（计算/校验/格式化都不在这里）                 │
└──────────────────────────────▲──────────────────────────────┘
                               │  props / callbacks
┌──────────────────────────────┴──────────────────────────────┐
│  ViewModel = Custom Hooks                                   │
│  - 每个页面/复杂组件配套一个 useXxxViewModel                 │
│  - 内部组合 React Query / Zustand / 本地 useState           │
│  - 输出 state（数据）+ actions（事件回调）+ derived（派生量）│
│  - 处理：副作用、表单校验、错误处理、loading 状态、跳转逻辑   │
└──────────────────────────────▲──────────────────────────────┘
                               │  API 调用 / DB 读写
┌──────────────────────────────┴──────────────────────────────┐
│  Model                                                      │
│  - 数据真源：服务端 (React Query) / 本地持久化 (Zustand)    │
│  - TypeScript 类型来自 packages/types（Orval 生成 + 手写）   │
│  - 不含业务逻辑（业务逻辑在 ViewModel 或后端服务层）         │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 文件命名

| 角色 | 路径 | 命名 |
|---|---|---|
| View 组件 | `apps/dashboard/app/orders/index.tsx` | 文件即页面 (Expo Router) |
| 子 View 组件 | `apps/dashboard/components/OrderTable.tsx` | PascalCase |
| ViewModel hook | `apps/dashboard/viewmodels/useOrdersViewModel.ts` | `useXxxViewModel` |
| Model 类型 | `packages/types/src/index.ts`（生成产物） | `Order`, `MenuItem` |
| API client | `packages/api-client/src/hooks/useGetOrders.ts`（Orval 生成） | `useXxx`（生成命名） |
| Zustand store | `apps/mobile/stores/cartStore.ts` | `useXxxStore` |

### 2.3 ViewModel 模式示例（参考代码）

```ts
// apps/mobile/viewmodels/useLoginViewModel.ts
import { useState } from 'react';
import { useRouter } from 'expo-router';
import * as SecureStore from 'expo-secure-store';
import AsyncStorage from '@react-native-async-storage/async-storage';
import { useSendSmsCode, useLogin } from '@restaurant/api-client/hooks';
import Toast from 'react-native-root-toast';

export function useLoginViewModel() {
  const router = useRouter();

  // 表单态
  const [phone, setPhone] = useState('');
  const [code, setCode] = useState('');
  const [agreed, setAgreed] = useState(false);

  // 倒计时
  const [countdown, setCountdown] = useState(0);

  // 服务端动作
  const sendCode = useSendSmsCode();
  const login = useLogin();

  // 派生量
  const canSubmit =
    /^1[3-9]\d{9}$/.test(phone) &&
    code.length === 6 &&
    agreed &&
    !login.isPending;

  // 事件
  const handleSendCode = async () => {
    if (!/^1[3-9]\d{9}$/.test(phone)) {
      Toast.show('请输入正确的手机号', { type: 'error' });
      return;
    }
    await sendCode.mutateAsync({ phone });
    // 启动 60s 倒计时
    setCountdown(60);
    const timer = setInterval(() => {
      setCountdown((s) => {
        if (s <= 1) { clearInterval(timer); return 0; }
        return s - 1;
      });
    }, 1000);
  };

  const handleSubmit = async () => {
    if (!canSubmit) return;
    try {
      const data = await login.mutateAsync({ phone, code });
      await SecureStore.setItemAsync('access_token', data.accessToken);
      await SecureStore.setItemAsync('refresh_token', data.refreshToken);
      await AsyncStorage.setItem('user', JSON.stringify(data.user));
      router.replace(data.user.role === 'staff' ? '/staff/workbench' : '/customer/home');
    } catch (e: any) {
      Toast.show(e.message ?? '登录失败', { type: 'error' });
    }
  };

  return {
    // state
    phone, code, agreed, countdown,
    isSubmitting: login.isPending,
    canSubmit,
    // actions
    setPhone, setCode, setAgreed,
    handleSendCode, handleSubmit,
  };
}
```

### 2.4 View 组件示例（参考代码）

```tsx
// apps/mobile/app/login.tsx
import { View, Text, TextInput, Pressable } from 'react-native';
import { useLoginViewModel } from '../viewmodels/useLoginViewModel';
import { Checkbox } from '@/components/Checkbox';
import { tokens } from '@restaurant/shared/tokens';

export default function LoginScreen() {
  const vm = useLoginViewModel();

  return (
    <View style={styles.container}>
      <TextInput
        value={vm.phone}
        onChangeText={vm.setPhone}
        placeholder="请输入手机号"
        keyboardType="number-pad"
        maxLength={11}
        style={styles.input}
      />

      <View style={styles.codeRow}>
        <TextInput
          value={vm.code}
          onChangeText={vm.setCode}
          placeholder="请输入验证码"
          keyboardType="number-pad"
          maxLength={6}
          style={[styles.input, styles.codeInput]}
        />
        <Pressable
          onPress={vm.handleSendCode}
          disabled={vm.countdown > 0}
          style={styles.getCodeBtn}
        >
          <Text>{vm.countdown > 0 ? `${vm.countdown}s` : '获取验证码'}</Text>
        </Pressable>
      </View>

      <Checkbox checked={vm.agreed} onChange={vm.setAgreed} label="我已阅读并同意..." />

      <Pressable
        onPress={vm.handleSubmit}
        disabled={!vm.canSubmit}
        style={[styles.submitBtn, !vm.canSubmit && styles.submitBtnDisabled]}
      >
        <Text style={styles.submitText}>
          {vm.isSubmitting ? '登录中...' : '登录 / 注册'}
        </Text>
      </Pressable>
    </View>
  );
}
```

**关键点**：
- View 不直接调 axios、不直接读 SecureStore、不直接调 router
- View 不写 `if (phone.length === 11 && ...)` 之类的派生逻辑（应在 ViewModel 的 `canSubmit`）
- View 不写 try/catch（错误处理在 ViewModel）

## 3. 状态分层（重要）

| 状态类型 | 工具 | 例 |
|---|---|---|
| **服务端数据**（订单列表、菜单、KPI） | React Query | `useQuery({ queryKey: ['orders', filters], queryFn })` |
| **服务端动作**（创建订单、状态机） | React Query useMutation | `useMutation({ mutationFn: createOrder })` |
| **跨页持久化本地态**（购物车、登录态、设置） | Zustand + persist (AsyncStorage) | `useCartStore()` |
| **页面级临时态**（表单输入、模态开关、Tab 选中） | `useState` / `useReducer` | 直接在 ViewModel 里 |
| **跨组件传递但不持久化**（主题、当前用户） | React Context | `<UserContext.Provider>` |

**反例**：把购物车放 React Query → 错。购物车是本地态，没有服务端真源，应用 Zustand。

## 5. 设计令牌使用

**严格通过令牌**，禁止硬编码颜色/字号/间距：

```ts
// ❌ 不要
<View style={{ backgroundColor: '#F59E0B', padding: 16 }} />

// ✅ 用令牌
import { tokens } from '@restaurant/shared/tokens';
<View style={{ backgroundColor: tokens.colors.primary, padding: tokens.spacing.md }} />
```

令牌定义见 `packages/shared/tokens/`，对照表见 [ai需求.md](../产品需求/ai需求.md) §2。

## 6. 网络层规范

### 6.1 axios 实例（全局唯一）

```ts
// packages/api-client/src/axios.ts
import axios from 'axios';
import * as SecureStore from 'expo-secure-store';

export const api = axios.create({
  baseURL: process.env.EXPO_PUBLIC_API_BASE,
  timeout: 10000,
});

api.interceptors.request.use(async (config) => {
  const token = await SecureStore.getItemAsync('access_token');
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

api.interceptors.response.use(
  (res) => res,
  async (err) => {
    if (err.response?.status === 401) {
      // 触发登出
      const { handleLogout } = await import('../stores/authStore').then((m) => m.useAuthStore.getState());
      handleLogout();
    }
    return Promise.reject(err);
  },
);
```

### 6.2 Orval 生成的 hooks（不手改）

```ts
// 自动生成的 packages/api-client/src/hooks/useGetOrders.ts
export const useGetOrders = (params: GetOrdersParams) =>
  useQuery({ queryKey: ['orders', params], queryFn: () => api.get('/api/orders', { params }) });
```

ViewModel 里直接消费：

```ts
const { data, isLoading, error } = useGetOrders({ status: 'pending' });
```

## 7. 测试规范

### 7.1 ViewModel 单元测试（Vitest）

ViewModel 是纯 hook，可在测试环境 `renderHook` 调用：

```ts
import { renderHook, act } from '@testing-library/react-hooks';
import { useLoginViewModel } from './useLoginViewModel';

test('phone 校验通过且 code 6 位 + agreed → canSubmit true', () => {
  const { result } = renderHook(() => useLoginViewModel());
  act(() => {
    result.current.setPhone('13800138001');
    result.current.setCode('123456');
    result.current.setAgreed(true);
  });
  expect(result.current.canSubmit).toBe(true);
});
```

### 7.2 View 组件测试（不必要）

View 是纯 props 渲染，重在视觉。不写单元测试，靠 Playwright E2E 截图测试 + 视觉巡检。

## 8. 反例清单（不要这么写）

```tsx
// ❌ 反例 1：View 直接调 axios
export default function OrdersScreen() {
  useEffect(() => { axios.get('/api/orders').then(...) }, []);
  // → 应在 useOrdersViewModel 里
}

// ❌ 反例 2：View 写业务逻辑
export default function OrderCard({ order }) {
  const canCancel = order.status === 'pending' || order.status === 'confirmed';
  // → canCancel 应在 ViewModel 派生
}

// ❌ 反例 3：硬编码颜色
<View style={{ color: '#F59E0B' }} />
// → 用 tokens.colors.primary

// ❌ 反例 4：ViewModel 返回 JSX
export function useFooViewModel() {
  return { render: () => <View /> };
}
// → ViewModel 只返回 state + actions，不返回 JSX

// ❌ 反例 5：把服务端数据放 Zustand
useStore.setState({ orders: await fetch(...) });
// → 服务端数据用 React Query

// ❌ 反例 6：把购物车放 React Query
useQuery({ queryKey: ['cart'], queryFn: () => localStorage.getItem('cart') });
// → 本地态用 Zustand
```

## 10. 落地顺序

搭骨架时严格按以下顺序，确保契约链跑通后再写 UI：

1. ✅ 后端 Drizzle schema（已完成）
2. ✅ 后端 drizzle-zod validators（已完成）
3. ⬜ 后端 Hono OpenAPI 文档输出（`/api/openapi.json`）
4. ⬜ `pnpm gen:contract`：Orval 读 OpenAPI → 生成 `packages/api-client` + `packages/types`
5. ⬜ `packages/shared/tokens/`：写设计令牌
6. ⬜ `apps/dashboard`：Expo Router 骨架 + 侧边栏 + 一个最小页面跑通契约链
7. ⬜ `apps/mobile`：Expo Router 骨架 + 登录页 + Tab Navigator
8. ⬜ 按 MVVM 分层，先写 ViewModel，再写 View
9. ⬜ E2E 测试覆盖关键流程

**禁止跳过 3-4 步**——这是项目地图最重要的"契约纪律"，跳过会被扣分。
