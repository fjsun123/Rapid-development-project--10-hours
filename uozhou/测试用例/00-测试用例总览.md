## 2. 测试环境

### 2.1 启动命令

```bash
# 1. 数据库（需 PostgreSQL 跑在 5432，库名 restaurant）
createdb restaurant 2>/dev/null || true
pnpm db:push
pnpm db:seed

# 2. 后端（端口 3001）
pnpm dev:backend

# 3. 后台管理 Web（端口 3000）
pnpm dev:dashboard

# 4. App（Expo Web 端口 8081；扫码可调试 Native）
pnpm --filter @restaurant/mobile dev    # 注：MVP 阶段如尚未拆分，则后台与App 同走 dashboard
```

### 2.2 测试地址

| 端 | 地址 |
|---|---|
| 后端 API | http://localhost:3001/api |
| 后台管理 Web | http://localhost:3000 |
| App Web 调试 | http://localhost:8081 |
| 后端健康检查 | http://localhost:3001/api/health |

### 2.3 浏览器要求

- 后台管理：Chrome 120+ / Safari 17+，分辨率 ≥ 1280×800
- App Web 调试：Chrome 120+，开 DevTools 移动模式（iPhone 14 / 390×844）

## 3. 测试账号（按 seed 数据约定）

| 角色 | 登录方式 | 账号 | 密码 / 验证码 |
|---|---|---|---|
| 平台管理员 | 后台管理 `/login` | `admin` | `admin123` |
| 商家 - 店长/员工 | App 短信登录 | `13800138000`（员工小王） | 见下方 ⚠️ |
| 客户 - 张三 | App 短信登录 | `13800138001` | 见下方 ⚠️ |
| 客户 - 李四 | App 短信登录 | `13800138002` | 见下方 ⚠️ |
| 客户 - 新用户（自动注册） | App 短信登录 | 任意未注册 11 位手机号 | 见下方 ⚠️ |

> ⚠️ **验证码不固定**：实际后端 `POST /api/auth/sms/code` 每次随机生成 6 位。
> - **开发环境**：响应体里返回 `_code` 字段（只在 NODE_ENV=development 时），测试时直接取响应的 `_code`
> - **生产环境**：靠真实短信网关
> - **测试代码示例**：
>   ```ts
>   const res = await ctx.post('/api/auth/sms/code', { data: { phone } });
>   const { _code } = await res.json();
>   await ctx.post('/api/auth/login', { data: { phone, code: _code } });
>   ```
>
> ⚠️ **状态机端点修正**：实际后端是 4 个独立 POST 端点，**不是** PATCH /status：
> - `POST /api/orders/:id/confirm` (pending → confirmed)
> - `POST /api/orders/:id/ready`    (confirmed → ready)
> - `POST /api/orders/:id/complete` (ready → completed)
> - `POST /api/orders/:id/cancel`   (任意非终态 → cancelled)
>
> ⚠️ **客户订单查询端点**：客户端用 `GET /api/customers/:id/orders`（已实现），不是 `/api/customer/orders`。
>
> ⚠️ **staff/admin seed 账号**：后端 `db/index.ts` 启动时自动 seed：
> - `{phone: 'admin', name: '管理员', role: 'admin'}` → admin login 用 username='admin' password='admin123'
> - `{phone: '13800138000', name: '员工小王', role: 'staff'}` → 短信验证码登录

## 7. 优先级定义

| 级别 | 定义 | 准入要求 |
|---|---|---|
| **P0** | 核心流程，阻塞发布。如：登录、创建订单、状态机流转、金额计算 | 100% 通过 |
| **P1** | 重要功能，影响体验。如：筛选、搜索、表单校验、空状态 | ≥ 95% 通过 |
| **P2** | 边缘场景 / 视觉细节。如：吐司位置、动画、悬浮态 | ≥ 80% 通过 |
