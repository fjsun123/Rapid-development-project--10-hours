页面名称：客户端订单列表（customer_orders）

> MVP 版本：RN App（客户自己的订单列表，只保留 Tab 筛选 + 客户取消，不做催单/再来一单/评价）
> 技术栈：Expo SDK 51+ + Expo Router (file-based) + TypeScript
> 状态管理：React Query for 服务端态；Zustand for 本地态（购物车持久化到 AsyncStorage）
> 表单：react-hook-form + zod
> 样式：StyleSheet.create + 设计令牌
> 鉴权：JWT 存 expo-secure-store，axios interceptor 注入 Authorization
> 网络：axios + Orval 生成 client
> 图片：expo-image

基本信息
页面ID：customer_orders_001

入口：底部 Tab「订单」（仅 role='customer' 时显示）

路由：`/(customer)/orders`（Expo Router file-based，`app/(customer)/orders.tsx`）

状态：正常 / 加载（骨架屏）/ 空态 / 异常（带 Retry 按钮）

元素清单（带ID）

1. 状态筛选 Tab（cust-order-tabs-001）
水平滚动：全部、待接单（pending）、制作中（preparing）、待出餐（ready）、已完成（completed）、已取消（cancelled）
  - **RN 实现**：`<ScrollView horizontal>` + 自封装 Tab 组件；切换时变更 `useState` 的 `activeStatus`，由 React Query `queryKey` 自动重拉

2. 订单列表（cust-order-list-001）
订单卡片（cust-order-card-001）：订单号（后 6 位）、下单时间（`dayjs(createdAt).format('MM-DD HH:mm')`）、总金额、状态徽章、菜品缩略（最多 2 行，超出 `numberOfLines={2}` + 省略号）

操作按钮组（cust-order-actions-001）：根据 `status` 动态显示：
- `pending`（待接单） → 显示「取消订单」（仅此状态可取消）
- `preparing` / `ready` / `completed` / `cancelled` → **无操作按钮**（MVP 砍催单/再来一单/评价）

容器：`<FlatList>` + `<RefreshControl />`（下拉刷新）+ `onEndReached={fetchNextPage}`（上拉加载更多，配合 `useInfiniteQuery`）
  - **RN 代码**：
    ```ts
    <FlatList
      data={pages.flatMap(p => p.items)}
      keyExtractor={(o) => String(o.id)}
      renderItem={({ item }) => <OrderCard order={item} />}
      refreshControl={<RefreshControl refreshing={isRefetching} onRefresh={refetch} />}
      onEndReached={() => hasNextPage && fetchNextPage()}
      onEndReachedThreshold={0.5}
      ListEmptyComponent={<Empty />}
      ListFooterComponent={isFetchingNextPage ? <ActivityIndicator /> : null}
    />
    ```

3. 空状态（cust-order-empty-001）
插图 + 文案「暂无订单，去点餐吧」，按钮跳转到点餐 Tab
  - **RN 实现**：`router.push('/(customer)/home')`

4. 列表骨架屏（cust-order-skeleton-001）
首屏加载时显示 3-5 张卡片骨架

交互逻辑

A. 状态筛选（cust-order-filter）
触发：点击顶部 Tab

行为：更新 `activeStatus` → React Query 自动以新 `queryKey` 重拉
  - **RN 代码**：
    ```ts
    const { data, refetch, isRefetching, fetchNextPage, hasNextPage, isFetchingNextPage } =
      useInfiniteQuery({
        queryKey: ['customer-orders', user.id, activeStatus],
        queryFn: ({ pageParam = 1 }) =>
          api.get(`/api/customers/${user.id}/orders`, {
            params: { status: activeStatus === 'all' ? undefined : activeStatus, page: pageParam, size: 15 },
          }).then(r => r.data),
        getNextPageParam: (last, all) => last.hasMore ? all.length + 1 : undefined,
        initialPageParam: 1,
      });
    ```

B. 取消订单（cust-order-cancel）
触发：点击「取消订单」按钮（仅 `pending` 状态订单可见）

行为：`Alert.alert` 二次确认「确定取消该订单吗？」 → 确认后调用 `POST /api/orders/:id/cancel` → 成功 toast「订单已取消」并 `queryClient.invalidateQueries({ queryKey: ['customer-orders'] })`；失败 toast 错误信息
  - **RN 代码**：
    ```ts
    Alert.alert('取消订单', '确定取消该订单吗？', [
      { text: '再想想', style: 'cancel' },
      { text: '确定取消', style: 'destructive', onPress: async () => {
        try {
          await api.post(`/api/orders/${order.id}/cancel`);
          Toast.show('订单已取消');
          queryClient.invalidateQueries({ queryKey: ['customer-orders'] });
        } catch (e) { Toast.show(parseErr(e)); }
      }},
    ]);
    ```
  - ⚠️ **后端潜在 bug**：当前 `POST /api/orders/:id/cancel` 端点**没有限制 customer 只能取消自己的订单**（admin/staff 也用同一端点），需要后端补「`req.user.role === 'customer'` 时校验 `order.customerId === req.user.id`」的鉴权。客户端先正常调用，但要在 Issue 中记录该后端缺陷

C. 订单卡片点击（cust-order-card-click）
触发：点击卡片任意区域（除「取消订单」按钮外）

行为：`router.push({ pathname: '/(customer)/order-detail/[id]', params: { id: order.id } })`
  - **RN 实现**：按钮区用 `<Pressable onPress={...} onStartShouldSetResponder={() => true}>` 阻止事件冒泡
