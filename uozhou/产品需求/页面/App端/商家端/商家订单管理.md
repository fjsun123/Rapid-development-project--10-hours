页面名称：商家订单管理（staff_orders）

> MVP 版本：RN App（商家端）。本 MD 是该页面的 React Native / Expo 落地说明，前端工程师可直接照写。

> 技术栈：Expo SDK 51+ + Expo Router (file-based) + TypeScript
> 状态管理：React Query for 服务端态；Zustand for 本地态
> 表单：react-hook-form + zod
> 样式：StyleSheet.create + 设计令牌
> 鉴权：JWT 存 expo-secure-store，axios interceptor 注入 Authorization
> 网络：axios + Orval 生成 client

基本信息
页面ID：staff_orders_001

入口：底部 Tab「订单」（仅 role='staff' 时显示，由 Expo Router 的 `(staff)/_layout.tsx` 控制可见性）

角色：服务员 / 店长可见全部订单（MVP 一期仅服务员/店长视角；后厨简化视图已砍）

文件位置（建议）：`app/(staff)/orders/index.tsx`

元素清单（带ID）

1. 顶部状态筛选 Tab（staff-order-tabs-001）
水平滚动 Tab：全部、待接单、制作中、待出餐、已完成、已取消

当前选中高亮，下方指示条
- **RN 实现**：自封装组件 `<OrderStatusTabs>`，外层 `ScrollView horizontal showsHorizontalScrollIndicator={false}`，子项 `<Pressable>`；当前选中态用 Zustand `useOrderFilterStore` 持有，避免每次切换都引发整树 re-render

2. 订单列表（staff-order-list-001）
订单卡片（staff-order-card-001）：包含订单号、下单时间、桌号/客户名、总金额、状态徽章、菜品缩略（最多2行）、操作按钮组
- **RN 实现**：使用 `FlatList`，`keyExtractor={(item) => item.id}`，`renderItem` 渲染 `<OrderCard>`；菜品缩略用 `numberOfLines={2}` + `ellipsizeMode="tail"` 截断

操作按钮组（staff-order-actions-001）：根据订单当前状态动态显示，例如「接单」「开始制作」「出餐」「完成」「取消」
- **RN 实现**：抽出 `getAvailableActions(status): Action[]` 纯函数；按钮一律 `<Pressable>`，命中区域用 `hitSlop={{ top: 8, bottom: 8, left: 8, right: 8 }}` 保证 44×44dp

3. 创建订单浮动按钮（staff-order-fab-001）
右下角圆形加号，仅服务员/店长可见，点击跳转点餐页
- **RN 实现**：绝对定位 `position: 'absolute', right: 16, bottom: 24 + insets.bottom`（用 `useSafeAreaInsets()` 避开 Home Indicator）

4. 空状态（staff-order-empty-001）
插图 + 文案「暂无订单，试试切换筛选条件」
- **RN 实现**：作为 `FlatList` 的 `ListEmptyComponent` 传入

5. 列表骨架屏（staff-order-skeleton-001）
3～5个卡片骨架，每个卡片包含头像、文字行占位
- **RN 实现**：`react-content-loader/native` 或 `moti/skeleton`；在 `isPending && !data` 时显示

6. 错误重试（staff-order-error-001）
网络错误时显示「加载失败，点击重试」
- **RN 实现**：`isError` 时显示 `<Pressable onPress={() => refetch()}>`

交互逻辑

A. 状态筛选（staff-order-filter）
触发：点击顶部 Tab

行为：列表显示局部加载 → 请求 `GET /api/orders?status=xxx&page=1&size=20` → 渲染新列表，保留滚动位置

空结果：显示空状态

- **RN 代码**：
```ts
const status = useOrderFilterStore((s) => s.status);
const { data, isPending, isError, refetch, isRefetching } = useQuery({
  queryKey: ['orders', { status }],
  queryFn: () => api.listOrders({ status, page: 1, size: 20 }),
  placeholderData: keepPreviousData, // 切换 Tab 时保留旧数据，避免闪烁
});
```

B. 订单卡片点击（staff-order-card-click）
触发：点击卡片任意区域（除操作按钮外）

行为：跳转订单详情页（Expo Router `push('/(staff)/orders/[id]')`）

- **RN 代码**：
```ts
import { router } from 'expo-router';
<Pressable onPress={() => router.push(`/(staff)/orders/${order.id}`)}>
```
- 操作按钮组用 `<Pressable onPress={(e) => { e.stopPropagation?.(); /* 业务 */ }}>` 阻止冒泡（RN 上更稳妥的做法是按钮直接放在 `Pressable` 卡片之外的兄弟节点，或卡片包裹层不用 Pressable，而是让卡片主体单独是 Pressable）

C. 状态操作（staff-order-status-action）
触发：点击操作按钮（如「接单」「开始制作」「出餐」「完成」「取消」）

行为：
- 若操作为「取消」，弹出二次确认对话框（`Alert.alert` 或自封装 `<ConfirmModal>`）
- 调用对应的**独立**状态机端点（**不是** `PATCH /status`）：
  - 接单：`POST /api/orders/:id/confirm`
  - 出餐（confirmed → ready）：`POST /api/orders/:id/ready`
  - 完成（ready → completed）：`POST /api/orders/:id/complete`
  - 取消：`POST /api/orders/:id/cancel`
- 按钮显示 loading，禁用所有操作
- 成功：吐司「订单状态已更新」，使 `['orders']` query 失效；若状态变更后该卡片不再符合当前 Tab，react-query 重拉后自然从列表移除
- 失败：吐司错误原因，按钮恢复

- **RN 代码**（以「接单」为例）：
```ts
const queryClient = useQueryClient();
const { mutate, isPending } = useMutation({
  mutationFn: (orderId: string) => api.confirmOrder(orderId),
  onSuccess: () => {
    Toast.show('订单状态已更新', { duration: Toast.durations.SHORT });
    queryClient.invalidateQueries({ queryKey: ['orders'] });
  },
  onError: (e) => Toast.show(getErrorMessage(e)),
});

<Pressable disabled={isPending} onPress={() => mutate(order.id)}>
  {isPending ? <ActivityIndicator /> : <Text>接单</Text>}
</Pressable>
```

- **取消二次确认**：
```ts
Alert.alert('确定取消该订单吗？', '取消后不可恢复。', [
  { text: '再想想', style: 'cancel' },
  { text: '确认取消', style: 'destructive', onPress: () => cancelMutation.mutate(order.id) },
]);
```

D. 创建订单（staff-order-fab-click）
触发：点击浮动按钮

行为：`router.push('/(staff)/orders/create')`

关联文档
路由：`/(staff)/orders`（Expo Router file-based）

接口（实际后端端点）：

- `GET /api/orders?status={status}&page=1&size=20` 列表
- `POST /api/orders/:id/confirm` 接单（pending → confirmed）
- `POST /api/orders/:id/ready` 出餐（confirmed → ready）
- `POST /api/orders/:id/complete` 完成（ready → completed）
- `POST /api/orders/:id/cancel` 取消

> 鉴权：所有请求由 axios interceptor 从 `expo-secure-store` 读取 `access_token` 并注入 `Authorization: Bearer <token>` 头。

- 列表骨架屏（可后置，先用 `<ActivityIndicator>` 占位）
